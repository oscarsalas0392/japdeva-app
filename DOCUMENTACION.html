JAPDEVA App — Documentación

App móvil Ionic + Angular standalone para la gestión de reclamos de JAPDEVA. Soporta usuarios externos (clientes) y usuarios internos (empleados).

Ionic 8 Angular 20 Capacitor 8 NGXS 20 TypeScript

3. Variables de entorno

Hay dos archivos: src/environments/environment.ts (desarrollo) y src/environments/environment.prod.ts (producción).

Angular sustituye dev → prod automáticamente con ng build --configuration=production via fileReplacements en angular.json.

Estructura

export const environment = {
  production: false,
  apiUrl:    'https://...',     // URL base del API Gateway
  timeoutMs: 30000,             // Timeout de cada request
  endpoints: {
    usuarios:    { ... },
    parametros:  { ... },
    reclamos:    { ... },
    envioCorreos:{ ... },
  },
};

Los dos archivos deben tener la misma estructura. Si se agrega un endpoint en environment.ts, hay que replicarlo en environment.prod.ts o el build de producción falla con TS2339: Property 'X' does not exist.

La URL hoy apunta a un túnel ngrok (temporal). Para producción, sustituir por un dominio fijo del API Gateway.

5. Estado global (NGXS) y persistencia

El state vive en un solo @State genérico que actúa como diccionario clave/valor:

// app.state.ts
@State<Record<ClaveEstado, unknown>>({ name: 'app', defaults: {} })

Se manipula desde EstadoAppService:

await estadoService.guardar(ClavesEstado.usuario, datosUsuario);
const usuario = await estadoService.obtener<UsuarioModel>(ClavesEstado.usuario);
await estadoService.eliminar(ClavesEstado.menus);
await estadoService.limpiar();           // Wipe completo (al cerrar sesión)

Persistencia automática

main.ts configura @ngxs/storage-plugin para que la slice app se sincronice a localStorage en cada cambio:

provideStore(
  [EstadoApp],
  withNgxsStoragePlugin({ keys: ['app'] }),
),
El state sobrevive recargas (F5 web) y reapertura de la app móvil. Cuando se hace limpiar(), también se borra de localStorage. No guardar credenciales o tokens aquí — eso va en Preferences (ver siguiente sección).

6. Almacenamiento local seguro

Para datos sensibles usamos Capacitor Preferences vía AlmacenamientoService:

  • En Android usa SharedPreferences (privado a la app).
  • En iOS usa UserDefaults (privado a la app).
  • En web cae a localStorage.

Claves

ClaveContenido
tokenJWT Bearer del usuario
correo_recordadoCorreo para "Recordar correo"
biometria_habilitadaFlag 'true' si activó huella/Face ID

API

await almacenamiento.guardar(ClavesAlmacenamiento.token, jwt);
const token = await almacenamiento.obtener(ClavesAlmacenamiento.token);
await almacenamiento.eliminar(ClavesAlmacenamiento.token);
await almacenamiento.limpiar();

Las credenciales biométricas (usuario + contraseña para la huella) se guardan en el Keychain nativo vía capacitor-native-biometric, no en Preferences.

7. Autenticación y guards

Flujo de login

  1. Usuario ingresa correo + contraseña (o usa huella).
  2. AuthService.autenticar() → POST /Usuarios/api/Auth/Autenticar.
  3. La respuesta trae el JWT en Token. ApiService lo guarda automáticamente en Preferences vía guardarToken().
  4. Se persiste usuario, idRol, usuarioRol, departamentoUsuario, menus en el state NGXS.
  5. navegarSegunRol() redirige a /inicio-usuario-interno o /inicio según el rol.

Roles internos

Definidos en roles.constants.ts:

export const ROLES_INTERNOS: readonly number[] = [1, 2, 3];

Si querés agregar otro rol interno, solo modificar esa lista — el guard y el componente raíz se actualizan automáticamente.

Guards

GuardQué chequeaSi falla
authGuardExiste token en Preferences y usuario en stateRedirige a /inicio-sesion
rolInternoGuardidRol ∈ ROLES_INTERNOSRedirige a /inicio
rolExternoGuardidRol ∉ ROLES_INTERNOSRedirige a /inicio-usuario-interno

Aplicación en rutas

{
  path: 'gestion-usuarios',
  canActivate: [authGuard, rolInternoGuard],
  loadComponent: () => import('./pages/gestion-usuarios/gestion-usuarios.page')
    .then(m => m.GestionUsuariosPage),
},

Interceptor HTTP

auth.interceptor.ts inyecta el header Authorization: Bearer <token> en cada request automáticamente. Lee el token desde Preferences vía Observable (from(...).pipe(switchMap(...))).

8. Capa HTTP y manejo de errores

Todo el tráfico HTTP pasa por ApiService. Los services específicos solo arman los parámetros.

Métodos disponibles

api.get<T>(endpoint, params?):  Promise<RespuestaModel<T>>
api.post<T>(endpoint, body):    Promise<RespuestaModel<T>>
api.put<T>(endpoint, body):     Promise<RespuestaModel<T>>
api.delete<T>(endpoint, params?): Promise<RespuestaModel<T>>

Modelo de respuesta uniforme

interface RespuestaModel<T> {
  Exito: boolean;
  Identificador: string;
  Mensaje: string;
  Datos?: T;
  Token?: string;        // Solo en respuestas de auth
  Manejado?: boolean;    // Ver siguiente sección
}

El normalizar() interno acepta tanto Exito/Datos como exito/datos (el backend a veces devuelve PascalCase y a veces camelCase).

Matriz de errores

Tipo de errorDetecciónAcción del ApiService
Timeout (tardó más que timeoutMs)TimeoutErrorPopup "Error" + expulsa al login
API inalcanzable (red, CORS, DNS)status === 0Popup "Error" + expulsa al login
Sesión expiradastatus === 401Popup "Sesión vencida" + expulsa al login
Error del servidorstatus ∈ [500, 599]Popup "Error" + expulsa al login
Otros (4xx)Cualquier otroSolo devuelve Mensaje en la respuesta

Expulsión segura

ApiService tiene dos protecciones:

  1. Flag expulsando — si varias requests fallan en paralelo, solo la primera dispara el popup y la navegación. Las demás se marcan como Manejado: true y devuelven silenciosamente.
  2. estaEnAplicacion() — si la request salió desde una pantalla pública (login/registro/olvido-contraseña), NO se expulsa. Esto evita loops y permite que el caller maneje el error normalmente.

El flag Manejado

Cuando el ApiService dispara su propio popup (401/500/timeout/network), retorna Manejado: true. Los pages deben respetarlo para no mostrar un segundo popup:

const respuesta = await this.miService.algo();

if (respuesta.Manejado) return;          // ApiService ya avisó al usuario
if (!respuesta.Exito) {
  this.popup.mostrar({ ... });            // Solo errores que no expulsan
  return;
}
// éxito

9. Caché de datos

Para datos relativamente estáticos del backend (parámetros de contacto, términos, ayuda), aplicamos el patrón stale-while-revalidate:

async ngOnInit(): Promise<void> {
  // 1. Mostrar cache inmediato si existe
  const cacheado = await this.estadoService.obtener<MiTipo>(ClavesEstado.miClave);
  if (cacheado) {
    this.aplicar(cacheado);
    this.cargando.set(false);
  }

  // 2. Refrescar en background
  const respuesta = await this.servicio.obtener();
  if (respuesta.Exito) {
    const nuevo = this.transformar(respuesta.Datos);
    if (JSON.stringify(nuevo) !== JSON.stringify(cacheado)) {
      this.aplicar(nuevo);
      await this.estadoService.guardar(ClavesEstado.miClave, nuevo);
    }
  }
  this.cargando.set(false);
}
Beneficio: la segunda visita es instantánea, sin spinner. Si el contenido cambió en el servidor, se actualiza solo cuando llega la respuesta.

Aplicado en:

  • terminos-condiciones.page.ts
  • informacion.page.ts (externo)
  • informacion-usuario-interno.page.ts

El departamento del usuario interno también se cachea: se lee del state primero, solo si falta se consulta al API.

11. Patrones del código

1. Standalone components + signals

Todos los componentes son standalone: true. Estado local con signals + ChangeDetectionStrategy.OnPush cuando es posible:

@Component({
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [...],
})
export class MiPage {
  readonly cargando = signal(true);
  readonly items    = signal<Item[]>([]);
}

2. Inyección con inject()

private readonly authService = inject(AuthService);
private readonly router      = inject(Router);

Más legible que el constructor con muchos parámetros.

3. paginaLista para Ionic transitions

Ionic a veces no termina la transición antes de renderizar el contenido. Para evitarlo:

readonly paginaLista = signal(false);

ionViewDidEnter(): void {
  this.paginaLista.set(true);
  this.cdr.markForCheck();
}

ionViewWillLeave(): void {
  this.paginaLista.set(false);
  this.form.reset();
}

En el template, envolver el contenido con @if (paginaLista()) { ... }.

4. NgZone para callbacks de plugins nativos

Los plugins de Capacitor (NativeBiometric, Filesystem, etc.) resuelven sus promesas fuera de la zona de Angular. Si modificás estado dentro del callback, la UI no se actualiza.

Patrón:

await NativeBiometric.verifyIdentity(...);  // ← sale de zona aquí

await this.ngZone.run(async () => {
  // Todo lo que actualice UI/state va acá adentro
  this.cargando = false;
  this.cdr.detectChanges();
  await this.router.navigate(['/inicio']);
});

5. Pasar datos entre pages

Hoy se usa history.state:

this.router.navigate(['/detalle', id], { state: { reclamo } });

// En el destino
ngOnInit() {
  const nav = history.state;
  if (nav?.reclamo) this.reclamo.set(nav.reclamo);
}
Esto se pierde al recargar la página. Si querés que sea robusto, pasá el ID por URL y hacé refetch en el destino. Para listas de resultados (como resultados-reclamos), conviene guardar los criterios en NGXS y reconstruir.

12. Cómo crear un page nuevo

  1. Crear carpeta y archivos bajo src/app/pages/mi-page/:
    • mi-page.page.ts
    • mi-page.page.html
    • mi-page.page.scss
  2. Esqueleto TS: 
    import { Component, inject, signal, ChangeDetectionStrategy } from '@angular/core';
import { TranslateModule } from '@ngx-translate/core';
import { PaginaComponent } from '../../components/pagina/pagina.component';

@Component({
  selector: 'app-mi-page',
  templateUrl: './mi-page.page.html',
  styleUrls: ['./mi-page.page.scss'],
  standalone: true,
  changeDetection: ChangeDetectionStrategy.OnPush,
  imports: [TranslateModule, PaginaComponent],
})
export class MiPage {
  readonly cargando = signal(true);
}
  3. HTML envuelto en <app-pagina>: 
    <app-pagina titulo="Mi título" [atras]="true" [cargando]="cargando()">
  <!-- contenido -->
</app-pagina>
  4. Registrar ruta en app.routes.ts: 
    {
  path: 'mi-page',
  canActivate: [authGuard, rolInternoGuard], // o rolExternoGuard, o solo authGuard
  loadComponent: () => import('./pages/mi-page/mi-page.page')
    .then(m => m.MiPage),
},
  5. Agregar traducciones en src/assets/i18n/es.json: 
    "miPage": {
  "titulo": "Mi título"
}
  6. (Opcional) Si el page tiene un botón en algún menú, agregarlo en el componente correspondiente (menu-usuario-interno o menu-usuario-externo).

13. Build para Android

# 1. Build de Angular + copia de assets a Android
npm run build:android

# 2. Sincronizar plugins nativos con Gradle
npx cap sync android

# 3. Abrir en Android Studio
npx cap open android

Cuándo correr npx cap sync

  • Después de instalar un plugin nuevo de Capacitor (ej. @capacitor/preferences).
  • Después de actualizar versiones de plugins.
  • Si Android no encuentra una clase nativa que existe en el plugin npm.

Permisos declarados

Capacitor maneja el AndroidManifest.xml parcialmente. Para permisos que se piden en runtime (almacenamiento al descargar archivos, biometría, etc.) ya están integrados en app.component.ts:solicitarPermisos() para Filesystem.

14. Troubleshooting

"NG04002: no route matched"

Probablemente agregaste un page nuevo pero olvidaste registrar la ruta en app.routes.ts. El error trae la ruta que se intentó usar.

"TS2339: Property 'X' does not exist on type" en environment

environment.ts y environment.prod.ts están desincronizados. Agregá la propiedad faltante al archivo prod.

Usuario logueado pero al recargar lo manda a login

El plugin de storage de NGXS no está hidratando el state. Verificar que main.ts tenga:

provideStore([EstadoApp], withNgxsStoragePlugin({ keys: ['app'] })),

Spinner se queda activo después de operación biométrica

El callback de NativeBiometric corre fuera de NgZone. Asegurate de envolver actualizaciones de estado y cdr.detectChanges() en this.ngZone.run(...).

El usuario ve dos popups en errores 401/500

Algún caller no está chequeando respuesta.Manejado. Agregar:

if (respuesta.Manejado) return;

antes del bloque que muestra el popup local.

"Provisional headers are shown" / la app no carga datos

El API no responde (status === 0). El ApiService ya detecta esto y expulsa a login automáticamente. Si querés debugear, mirá la URL en environment.ts — probablemente el túnel ngrok expiró.

Cambios de configuración de Android no se aplican

Después de tocar capacitor.config.ts, package.json o instalar plugins:

npm run build:android
npx cap sync android

Y reiniciar Android Studio si es necesario.
